## Objectives
1. **Atta answers the Den's reads by the Den's rules, on its own.** Done when: `cargo test -p atta` passes; `just gate` runs the guard that fails if Atta gains a workspace dependency, build ones included; Atta's last read-side slice carries a table mapping every Atta rule in the TDD's My Den security table and in the hiding change's test list to a named test (inherited standing, no page token after a refused tail, and a link failing closed as absent included). Serves: Atta's read side (WP-12).
2. **Zurfur answers Atta through one host and one exhaustive match, and no arm can break a read.** Each team's arm lives in a `den.rs` leaf of its module. Done when: `rg -n '^\s*_\s*=>' backend/crates/application/src/den*` and `rg -n 'todo!|unimplemented!|unreachable!|panic!|\.expect\(|\.unwrap\(' backend/crates/application/src -g '**/den.rs' -g '**/den/**' -g '!**/tests.rs'` print nothing; a test shows each arm's name conversion never fails on a value its own type accepts; the empty `/post/<did>` stub lands as its own slice, with the posts lead's review on it. 3. **Every miss looks the same, and the viewer comes only from the session.** Done when: on the dev profile, as alice, `/den/characters/<Abco's DID>` (exists, not hers) and `/den/characters/did:plc:nope` show the same "Nothing here"; `cargo test -p api --test den` lists and passes the test comparing status, body and every header but `date` across every not-found cause, the test that bob's DID as a path piece is that same 404 under alice's session, and the split-then-decode tests (`%2F`, `%252F`); `rg -n 'Path<|RawPathParams' backend/crates/api/src/routes/den*` and `rg -n -w atta backend/crates/api` print nothing. Serves: the den API routes (WP-19); "Nothing leaks".
4. **den.proto lives in the contract as you reviewed it, and the web tests against real answers.** Done when: the den.proto PR differs from the reviewed draft only by your review's edits, and also carries the id-rule text, `session.proto`'s comment and the new `400` error entry; CI's contract job passes; the route pin marks the two den routes as dev-profile only; on a fresh `jj new` above the golden-responses slice, its regenerate recipe then `jj diff --stat` prints nothing. 5. **My Den reaches `main` reviewed, and the corpus says what the code does.** Done when: `feature/my-den` is merged; `/close-gaps --post` is clean; the end-of-slice security review's file lists no open must-fix; the My Den rulings spell the query parameter as you rule on its spelling (D-7); `just nodes refs 2026100701` lists the Atta, den module and den routes nodes. ## Where the stages change our plan
- **den.proto closes for good at the alpha, not before.** The contract decision lets a breaking change before the first published client go in as its own declared "baseline reset" PR, and you ruled that the alpha is that client. Question 3 still puts your review first.
- **Hiding archived items after access is known (D-15) still needs your approval.** It changes an approved diagram, and that rule isn't about stages. Only the host trait has to wait (question 2).
- **Golden responses are a test fixture, not a promise.** Generated ones are regenerated on every contract change, never patched; the hand-written card fixtures stay marked as such.
- **Provisional type names (`commission`, …) are fine through pre-alpha.** Before the alpha tag they are settled, or accepted as they are.
- **Unchanged by the stage:** every rule in the TDD's My Den security table, from "the viewer comes from the session only" to "no payload served". Equal timing of the not-found stays a re-test at the Den's first PostgreSQL read.

## Not this release
- **Links in Atta.** 0.1 has none, and how a link to an archived item resolves is still open. Atta resolves no link yet; a link handed to it fails closed as absent (Atta grows only as real needs appear).
- **Later, under your scope ruling and Claude's answer to D-1:** writes, named actions and rendering; the Den on PostgreSQL and the everyday stack (0.2); `participants`; view grants; bringing a commission into an Account; dotfiles; the maturity gate in your own Den.
- **Moderation.** A hold needs no change to den.proto. Moderation's QA reviews the host check's inputs on the host-trait slice. Lockdown's "public pages off" is a read gate, due with the first slice that serves a node to anyone but its own viewer.
- **Missing from the plan, for the tech lead:** a guard that the API doesn't depend on Atta (now in objective 3); `just gate` and CI building the dev-profile feature, if the den routes or their tests sit behind it; the versioning contract's one-line "baseline reset" rule, ruled on 2026-08-30 and never written in, which any pre-alpha contract break needs.
- **Folders that always list empty.** An Account's `characters` and a commission's `products` list empty because nothing can be stored there yet. Each gets what the PostgreSQL keeper read got, for the tech lead to confirm: a doc comment, a pinning test, and an acceptance criterion on the slice that adds storage. Den agrees with the commission team's archived seed and slot message.

## Questions for the Engineer (each pre-answered)
1. **Your Atta draft (the plan's "What blocks the start", row 4): den's answer.** *Proposed:* build on it, with what your rulings force. `Key(Uuid)` becomes the path segment (My Den rulings, decision 2), so `parent` and `symlink_target` become real paths. The empty `Type` enum becomes an opaque type key. `NodeName` and the path segment get hand-written `TryFrom` and `FromStr` that enforce the name rules and the ASCII allowlist; their derived `From`, `FromStr` and `Deserialize` go, since each lets an unchecked value in (approved-crates decision, rule 9). **One fork:** The Den's closed metadata includes the payload's hash, and 0.1 has no payload. *Proposed:* 0.1's metadata leaves the hash out until the first payload; `Payload` and the attributes wait the same way.
2. **May Atta's first slices start before you approve D-15?** *Proposed:* yes. Path segments, names, levels and caps start when you sign; only the host trait waits. Before the sitting, the tech lead makes the hiding change's rule table match Claude's revised answer to its question 2; today they disagree on a view grant.
3. **Does your den.proto review still come before the den.proto package?** *Proposed:* yes, in this sitting; revision 2.1 is ready. A later change would go in as its own declared baseline reset. The id-rule change to the versioning contract waits for your review either way.
4. **No payload path in 0.1, in place of a verifier that refuses every payload?** You chose the refusing verifier when you ruled on serving metadata first. *Proposed:* the host trait gets no payload method in 0.1, so nothing can serve a payload, which is stronger than refusing one. The security row and the review checklist then read "no code path serves a payload". The verifier arrives with the first payload.
5. **How long may a node's name be, and what shows when a stored name fails?** *Proposed:* at most 2048 bytes, atproto's hard limit for a DID. A DID ends the User's name chain and is ASCII without `/` (atproto DID spec, read 2026-10-09), so that last step can't fail once identity's DID type takes the same cap. Today's capped names fit: a Workflow name (196 characters), a display name (640 bytes, `app.bsky.actor.profile`, read 2026-10-09), a file name (255 bytes). Commission titles, slot titles and character names, uncapped today, take a rule at least as strict as the Den's, pinned by a test (the commission team's question 3). A stored name that still fails shows the fixed word "Unnamed", never its key, and the read goes on.
