# 0.1 objectives: commission

Stage: pre-alpha-v0.1.0 · Lead: Wolf · QA: Jay

Our 0.1 work is two packages of "My Den, read-only, on the real backend": the commission read ports and fixtures (Raven), then the commission host arms (Egret), plus the one-line `is_archived` fix first. It all runs on the dev profile, under Claude's proposed answer to "Your own Den after a real sign-in" (side by side now, joined in 0.2), which you haven't signed yet. If you pick a joined 0.1, we also take on converging today's commission reads that bypass the Den, and serving our PostgreSQL reads for real.

## Objectives

1. **A commission you take part in shows up in My Den, with its parts.** Done when: on the dev-profile recipe, as alice: `commissions` lists "Untitled" (Private, mounted mark); it opens to exactly `attachments`, `products`, `slots` and the file `changelog`, each Private; `attachments` lists "ref-abco.png" and "sketch-01.png"; `products` says "This folder is empty."; `slots` lists Abco, Ember, Kael and Open slot; `changelog` and each file show their header and "Content not shown yet." Bob sees the same (if the user switch is cut: bob's golden response, path named in the golden-responses PR). Serves: the commission ports and fixtures; the commission host arms; "Look inside a commission I take part in".
2. **A Workflow appears, opens, and never looks empty.** Done when: as alice, Supreme Arts → `workflows` lists one Workflow, "Queue", Private; it opens to "Content not shown yet." and lists nothing, as does Supreme Arts' `commissions`. Serves: the Workflow listing and fixture; the commission host arms; "Browse a folder".
3. **Archived commissions stay out of listings unless asked for, open when typed, and carry the backend's word.** It rests on three things you haven't approved yet: the hiding decision ("Where archived and deactivated nodes are hidden"), and the soft-deleted word and its field name (your den.proto review). Done when: (a) the fixed `is_archived` is on `main`, as its own bug PR with a test, before `feature/my-den` is cut; (b) with question 1's seed, as alice: "Old sketch" is absent; with "Show archived and deactivated" on, it appears marked "Archived"; open it, copy the address, turn the toggle off, paste: it opens, marked; (c) `just test` runs the hiding amendment's "Tests that prove it", with our rows in its table-driven host test. Without the seed, (b) is seen on `just dev-mock` only. Serves: the commission host arms (keep-or-refuse, and the word); "Show archived and deactivated".
4. **The commission side leaks nothing.** Only Participants get a commission entry, read from the participant record today's authorization uses (an invitation gives none). Only a node's name, kind, own level, content flag and soft-deleted word leave our arms. Every name we serve (commission title, slot title, file name, Workflow name) passes one shared rule: no control or format characters (bidi overrides included), not empty, no `/`, and every valid value converts to the Den's name type, so a read never fails on a name. No arm panics, maps its own not-found, or logs a commission id, title, file key or name, or a DID. Done when: Heron's reviews of both packages show no open must-fix; `just test` runs the name tests (a right-to-left override and an isolate refused for each of the four names; "every valid value converts"); bob's and alice's golden responses hold no status, brief, deadline, owner, maturity or linked-channel value; as bob, the address of "Old sketch" shows "Nothing here" (question 1; else a named den-Query test). Serves: the security gates on the commission ports ("who counts as a Participant") and arms ("standing and levels"); "Nothing leaks".
5. **Every new read works on PostgreSQL too, so 0.2 joins My Den to your real sign-in without commission rework.** Five reads: the commissions a user takes part in (archived ones included, so the hiding check sees them), a commission's file list, a file's name without its bytes, a commission's slots, an Account's Workflows. Done when: `cargo test -p adapter-pg` runs green one named test per read, and the participant table has its by-user index. Serves: the tech lead's "both adapters, no stubs" rule, on which "side by side in 0.1, joined in 0.2" rests.

## Where the stages change our plan

- **Never relaxes:** objective 4 whole; Jay's QA and Heron's review on both packages; both adapters.
- **Relaxes:** tightened name rules ship without a data migration. Only your dev data exists; a stored row that fails them is cleared with `just db-reset`. The PR notes that commission create, file upload and slot declare start refusing such names.
- **Kept anyway:** the by-user participant index ships now (one additive migration, via `just migrate-add`), so 0.2 needs no commission migration.
- **Reversible until the alpha:** type names, fixture rows, and which types say "Content not shown yet" are server behaviour, not contract shape.
